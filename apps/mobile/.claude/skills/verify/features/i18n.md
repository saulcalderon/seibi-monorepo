# The app speaks Spanish from es.json

Every word Seibi shows comes from `src/i18n/es.json` through i18next. The
app opens in Spanish, also on a device set to English: Spanish is the
default, the device language only suggests one, and Seibi speaks only
Spanish until `en.json` lands. Text is ready on the first frame, so no
i18n key (`tabs.home`) ever shows. The tabs, Inicio, the actions sheet,
Perfil, sign-in, «Cuenta eliminada» and the delete-account alert take
their copy from `es.json`; the tab labels, Inicio's greeting and the
actions sheet are the proof, and this file grows with each screen. The
test sign-in form keeps its copy in its own module, so production bundles
carry none of it ([`auth.md`](./auth.md)).

## Sub-features

- `copy-from-es-json` shows the tabs «Inicio», «Mi flota», «Avisos», a greeting («Buenos días», «Buenas tardes» or «Buenas noches»), «Tu Vehículo», and the actions sheet's «¿Qué quieres hacer?», «Registrar un Servicio», «Actualizar Kilometraje».
- `no-keys` never shows a raw key such as `tabs.home`, not even on the first frame after the splash.
- `device-english` keeps Spanish on a device whose first language is English.
- `device-spanish` shows Spanish on a device set to Spanish.
- `ios-permission-strings` shows the camera and photo permission prompts in Spanish (from `locales/es.json`). Not drivable yet: no screen asks for them until S12.
- `ota-prompt` shows «Hay una versión nueva de Seibi» when an update is downloaded. Not drivable in a development build: updates are off there.

## How to get to it (user POV)

- Open the app from a cold start (`${DEV_URL}` in a development build) and sign in. Inicio is the first screen after sign-in; the [+] opens the actions sheet.
- Change the device language in Settings, then open the app again.

## Driving it with verify.sh

Preconditions:

- `verify.sh launch <ios|android>` ended with `doctor: OK`, with the test account set (`test user:` line).
- Seibi Dev is installed from the branch under test, built after `expo-localization` and `expo-sqlite` joined (SEI-43). An older build has neither native module and shows a red screen.

- **Spanish copy.** Run `.claude/skills/verify/scripts/verify.sh drive ios i18n-shell` (then `android`). The flow cold-starts the app, runs `sign-in.yaml` (signs in with the test account when signed out, ends on `id: home-screen`), then asserts «Inicio», «Mi flota», «Avisos», «Tu Vehículo» (or «Sin Vehículos todavía») and `id: home-greeting` reading a greeting. Screenshot `home-es`. It taps `id: open-actions` and asserts «¿Qué quieres hacer?», «Registrar un Servicio» and «Actualizar Kilometraje» (`actions-es`), then closes the sheet.
- **No keys.** The flow asserts no visible text matches `(tabs|shell|home|fleet|greeting|update)\..*` on Inicio and `actions\..*` on the sheet. The video shows the splash, then the Spanish text, with no frame of keys between them.
- **Device in English (iOS).** Check the simulator's languages: `xcrun simctl spawn <udid> defaults read -g AppleLanguages` (`verify.sh doctor ios` prints the UDID). A new `Seibi Verify` simulator copies the Mac's list, which may already start with English. To set it: `xcrun simctl spawn <udid> defaults write -g AppleLanguages -array en-US`, `xcrun simctl shutdown <udid>`, `verify.sh launch ios`, then drive. The flow passes unchanged: the text stays Spanish.
- **Device in Spanish (iOS).** The same with `-array es-SV` (any `es-*`), then drive. Restore the earlier list afterwards.
- **Device in English (Android).** Check `adb -s emulator-5560 shell getprop persist.sys.locale` (empty means the image default, `en-US`). The emulator is shared: don't change its system language. Drive as is; the flow passes unchanged.
- **Device in Spanish (Android).** Set the language for Seibi Dev only: `adb -s emulator-5560 shell cmd locale set-app-locales com.seibiapp.app.dev --locales es-SV`, drive, then clear it with `--locales ""` so the next session starts clean.
- **Proof.** The run folder holds `startRecording/i18n-shell.mp4` and `takeScreenshot/home-es.png`, `actions-es.png`. Save the language check's output next to them (for example `device-language.txt`): the flow can't tell which language the device had.

## Gotchas

- The flow can't read `es.json`: its expected text is a copy. Change both together.
- A red screen mentioning `ExpoLocalization` or `ExpoSQLite` means the installed build predates SEI-43: `launch <platform> --rebuild` after `expo prebuild --clean`.
- On Android, `verify.sh launch android` keeps whatever Seibi Dev is installed, even one another session built from another branch. Pass `--rebuild` (or `adb install -r` this branch's APK) before driving.
- The device language only matters when nothing is stored. A stored choice (`language.v1` in the app's kv-store) wins over it; a fresh install has none. Sign-out keeps it: it is a setting of the phone, not of the person.
- iOS reads the device language at launch; after changing it, reboot the simulator. Android keeps the app process across a language change, so cold-start the app (the flow's `stopApp` does).
